## №1 Написать однострочный скрипт, делающий следующее

Имея дело с однострочниками, нужно знать основы того, как разные бинарники могут взаимодействовать друг с другом без посредника в виде пользователя, который может сам читать/копировать/видеть данные с терминала и переносить их в другой бинарник. Это называется перенаправлением потоков.

Поток - инструмент для записи/чтения данных в память, использует файловый дескриптор - идентификатор, определяющий место для записи данных и место для их чтения (далее `fd`).

Основные три потока при взаимодействии с командной строкой:

-------

- `stdin` - стандартный ввод (поток №0)

- `stdout` - стандартный вывод, например в терминал (поток №1)

- `stderr` - стандартный вывод отладки (в т.ч. ошибок), обычно тоже терминал (поток №2)

Обычное взаимодействие: пишем в `stdin`, получаем комплексный ответ в `stdout` и `stderr`

```sh
echo 'hello'
```

Полезные операторы:

- `>` - создать файл(если существует, перезаписать) с названием справа и записать туда `stdout`

- `2>` - то же, но записывает `stderr`; прекрасно работает в сочетании с `2> /dev/null` (подавляет ошибку, записывая ее в исчезающий файл)

- `>>` - то же, но перезаписи не будет(если файл существует); угадай что делает `2>>`

Циферка 2 не случайна, если вспомнить нумерацию потоков

```sh
ls unknown_file
ls unknown_file 2> /dev/null
ls > hello
cat hello
echo 'hello' > hello
cat hello
echo 'world' >> hello
cat hello
ls unknown_file 2>> hello
cat hello
```

- `&&` - выполняет команду справа если команда слева выполнилась без ошибок(строже: если бинарник завершился и завершился с 0 кодом)

- `<` - перенаправляет уже ввод: в `stdin` команды слева загружается содержимое файла справа

- `|` - `stdin` справа заполняется `stdout` слева; называют трубой, пайпом, pipe

```sh
sleep 1 && sleep 2> /dev/null && sleep 10 # sleep 1 second, sleep needs an argument
sleep 1 && sleep 1 && sleep 1 # sleep 3 seconds
man grep | grep "GNU" # search in manual about grep rows which contains "GNU"
```

Все, остальное разобрать можно будет по ситуации

### Разбор

По порядку:

Переменные окружения - временные переменные, которые действительны пока живет оболочка терминала. Добавляются простым `dir=.` или другой директорией. Использовать позже можно, введя это же название с `$` в начале в команду: `ls $dir`

Продвинутым рекурсивным поиском занимается команда с названием... `find` 

```sh
find / # escape: Ctrl+C
dir=task1/test_cmake_search
find $dir
```

Надо уточнить суффикс `.cmake` для найденных файлов... Тут простейшая регулярка, `*` означает любые символы в любом количестве, а вместе со строчкой `.cmake` означает "как угодно начинается и оканчивается на .cmake" (бувально определение суффикса). Важны кавычки, потому что `*` вне строчки означает "любой файл в директории".

```sh
find $dir -name "*.cmake"
```

Нам нужно еще выполнить условие с копирайтом, попробуем сначала решить это для одного файла - первые строки можно посмотреть командой `head`, а именно первые пять, добавив аргумент `head -n 5`

```sh
head task1/test_cmake_search/valid0.cmake
head task1/test_cmake_search/valid0.cmake -n 5
```

Как определить что в строках есть копирайт любого регистра? Воспользуемся `grep`, а для того чтобы искать именно в первых пяти строках, будем искать не в файле, а в выводе `head`, а для этого как раз используем один из операторов. Не забываем про регистр, добавив флаг `-i` к `grep`.

```sh
grep -i "copyright" task1/test_cmake_search/valid0.cmake # simple searches in a whole file
head task1/test_cmake_search/valid0.cmake -n 5 | grep -i "copyright" # searches in stdout of a head
```

По идее, имея вывод `find`, мы могли бы применить вывод `head` для каждого файла для решения задачи - но это все еще не похоже на однострочник.
К счастью, `find` предлагает особый аргумент `-exec`, который сможет вызывать команды для каждого найденного файла за нас.

```sh
find $dir -name "*.cmake" -exec sh -c 'head "$1" -n 5 | grep -i "copyright"' sh {} \;
```

- `sh -c` это выполнение команды в оболочке `sh` (неявно выполняется при каждом вводе командой пользователем)

- `{}` - заменяется текущим найденным файлом

- `\;` - экранированная точка с запятой, нужна чтобы показать `exec` где заканчивается программа

- `$1` - первый аргумент, поданный в бинарник; в данном случае: в `sh {}` подставляется название файла, затем передается в исполняемый файл оболочки, а оттуда его уже можно будет достать с помощью обращению к номеру аргумента: `$0` это сам `sh`, а уже `$1` это название файла, которое перехватывается уже внутрь второй части фильтра

Итого, кажется два фильтра действительно применяются, но мы получаем вывод найденных строк `grep` и не получаем названия файлов. Исправим это, подавив вывод `grep`-а флагом `-q` и дополнительно выведя название файла используя аргумент `$1`.

### [Решение №1](task1/solution.sh)

```sh
find $dir -name "*.cmake" -exec sh -c 'head "$1" -n 5 | grep -qi "copyright" && echo $1' sh {} \;
# there are 4 valid files in test_cmake_search
```

>Каждую нечётную строчку ввода привести к верхнему регистру, а каждую чётную — к нижнему.
>
>Дополнительно в начале строк должны отрезаться все слова «a» и «an», если они есть, вне зависимости от регистра. Слово отделяется от других слов пробелами, т.е., если строка начинается с «And», то отрезать «An» не нужно.
>
>Если в конце строки нет знака препинания («.», «!», «?», «;», «:»), то к строке при выводе должна добавляться точка.

>Гарантируется, что в строках для разделения слов используются только единичные пробелы; пробелов в начале и конце строк нет, буквы только английские.

>Вводом являются все файлы, указанные в командной строке, а если они не указаны, то считывание должно производиться со стандартного ввода (stdin).

>Результаты работы выводятся в stdout.

Это простое преобразование замняет все `a` в файле на `x`.

#### Сборка `sed`

Лучший мануал по `sed` [тут](https://www.gnu.org/software/sed/manual/sed.html)

В начале нет пробелов + нужен артикл `a/an` + артикл будет отделен **одним** пробелом от другого слова => нужно искать **префиксы** 'a ' или 'an '

```reg
^(a|an)[:space:]
```

`^` - начало строки

`(a|an)` - вариативная группа - либо `a` либо `an`

`[:space:]` - любой символ, который интерпретируется как пробел

Интепретируя это в `sed` с использованием флага `I` - ignore case:

```sh
sed -E "s/^(a|an)[[:space:]]//I" tests/test_1_input.txt
```

Такие правила `sed` можно стакать через точку с запятой - таким образом можно назначить все фильтры из задания.
Например, добавим случай, когда артикл всего один в строке - больше слов нет, и поэтому за артиклом не стоит пробел(дальше то нет слова).

```txt
A
An
And
anaconda
```

Должно преобразоваться в(не учитывая остальные условия):

```txt


And
anaconda
```

```sh
sed -E '
    s/^(a|an)[[:space:]]//I;
    s/^(a|an)$//I;
'
```

- `$` - конец строки

Вторая строчка дословно означает: если `(a|an)` между началом и концом строки, удалить независимо от регистра.

Я очень не хотел это все засовывать в цикл, поэтому я порылся и нашел [тут](https://www.gnu.org/software/sed/manual/sed.html#Numeric-Addresses) как можно определить четность/нечетность строки, а [тут](https://www.gnu.org/software/sed/manual/sed.html#Upper_002fLower-case-conversion) как конвертировать в lower/upper case. Достроим скрипт еще двумя правилами:

```sh
sed -E '
    s/^(a|an)[[:space:]]//I;
    s/^(a|an)$//I;
    1~2 s/.*/\U&/;
    2~2 s/.*/\L&/;
'
```

- `.` - любой символ
- `*` - любое количество символов(использовали ранее в поиске по суффиксу)
- `1~2` - начиная с 1 строки, брать каждую вторую строку
- `\U&` - в upper case
- `\L&` - в lower case

Осталась пунктуация, ищем в конце строке суффикс, не начинающийся с других символов пунктуации **"[.?!:;]"** и добавляем туда точку. Сразу обработаем случай с пустой строкой - просто добавим точку:

```sh
sed -E '
    s/^(a|an)[[:space:]]//I;
    s/^(a|an)$//I;
    1~2 s/.*/\U&/;
    2~2 s/.*/\L&/;
    s/([^.?!:;])$/\1./;
    s/^$/./;
```

Ну и не забываем про интерфейс `cat` - загрузим аргументы в скрипт с его помощью:

### [Решение №2](task2/solution.sh)

```sh
cat $* | sed -E '
    s/^(a|an)[[:space:]]//I;

    1~2 s/.*/\U&/;

    s/^$/./;
'
```

### №3.1 Создание библиотеки

Идея задания - права пользования, идемпотентность команд и перехват ошибок.

#### Система прав

Права к файлу (в т.ч. директории) определяются тремя категориями - владелец `u`, группа `g`, которой принадлежит владелец и остальные `o`. Самих прав всего 3: чтение `r` [4] запись `w` [2] и выполнение `x` [1]. Отстутствие права обозначается `-` [0].

Сочетание этих прав создает 8 вариантов, и представляется цифрой восьмеричной системой счисления `oct`. Если категория пользователей может выполнять несколько операций, то значение права складывается.

- 7 - `rwx` все права

- 5 - `r-x` чтение и выполнение

- 4 - `r--` только чтение

- 0 - `---` нет прав

и т.д.

Вместе собранные три значения для трех категорий пользователей и определяют права доступа к файлу.

Эти значение можно выдавать с помощью команды `chmod`, а посмотреть можно в подробном выводе `ls -l`.  Первый символ определяет, является ли файл директорией, а последующие 9 в порядке от владельца до остальных определяют права символами.

`chmod` понимает цифровое значение выдачи прав.

```bash
chmod 755 task3
ls -l
```

Можно выдавать/отбирать права у существующего файла, обратившись по соответствующим символам:

```sh
chmod o-r task3 # OTHERS DISCARD READ
ls -l # r is missing in task3
chmod o+r task3 # OTHERS GRANT READ
ls -l # r is returned in task3
```

Помимо самих прав, можно менять и кто входит в категории прав с помощью `chown`. По сути, менять владельца и пользователя.

```sh
chown [OPTION]... [OWNER][:[GROUP]] FILE...
```

Можно менять сразу и владельца и пользователя, а можно отдельно.

```sh
chown user file.txt  # file.txt -> owner "user"
chown user:group file.txt  # file.txt -> owner "user", group "group"
chown :group file.txt # file.txt -> group "group"
```

#### Идемпотентность

> Идемпотентность - свойство объекта или операции, при повторном применении которой к этому объекту результат остаётся прежним, как и при первом применении. Проще говоря, если вы идемпотентную операцию выполните один раз или много раз, система изменится только один раз.

Ярким примером этого является любимая мною команда `touch` - она создает файл, а если он уже существовал, ничего с ним не сделает. С ее помощью я могу создавать файлы не беспокоясь, что созданный файл перезапишет старый, плюс могу повторять эту команду сколько угодно раз. Кстати, `chmod` тоже идемпотентен. Идемпотентность - важное свойство для стабильности системы.

Знакомые команды также имеют возможность стать идемпотентными. К примеру, создание директории `mkdir` с флагом `-p`  будет игнорировать уже существующие директории.

#### Перехват ошибок

- `||` - напоминает оператор ИЛИ из си и буквально им и является - вернет ИЛИ на статусы исполняемого файла слева, а затем справа; свойство сначала выполнять левую часть, и только при ошибке в левой части выполнять правую нещадно эксплуатируют (и не только в баше)

- `set -e` - немедленно прервет скрипт при ошибке(если она не обработана, например `||`)

- `trap` - вызовет команды при получении определенного сигнала внутри скрипта

- `test` - проверит бинарный оператор, вызовет ошибку если он неверен. Компактная версия `if`.

Простейшее сочетание для обработки любой ошибки внутри скрипта:

```sh
set -e
trap 'echo "Error: Script execution failed" >&2; exit 1' ERR
```

Обработаем еще неправильное использование скрипта, например, неверное количество аргументов.

Объявим функцию `usage` по подсказке внутри условия:

```sh
usage() {
    for msg in "$@"; do printf "%s\n" "${0##*/}: $msg" >&2; done
    echo "usage: ${0##*/} source group" >&2
    exit 1
}
```

Для первого скрипта нужно 2 аргумента, проверим их через `test` и `$#`. Если `test` вернет ошибку, вернем `usage`, который самостоятельно выйдет из скрипта.

```sh
test $# -eq 2 || usage
```

```sh
#!/bin/bash

set -e
trap 'echo "Error: Script execution failed" >&2; exit 1' ERR

usage() {
    for msg in "$@"; do printf "%s\n" "${0##*/}: $msg" >&2; done
    echo "usage: ${0##*/} source group" >&2
    exit 1
}

test $# -eq 2 || usage

LIBRARY_DIR="$1"
GROUP_NAME="$2"

mkdir -p "$LIBRARY_DIR"
chmod 755 "$LIBRARY_DIR"

echo "library v1.0" > "$LIBRARY_DIR/.library"
chmod 644 "$LIBRARY_DIR/.library"

mkdir -p "$LIBRARY_DIR/books" "$LIBRARY_DIR/authors"
chmod 755 "$LIBRARY_DIR/books" "$LIBRARY_DIR/authors"
chmod 755 "$LIBRARY_DIR/books" "$LIBRARY_DIR/authors"

chmod o-w "$LIBRARY_DIR/books" "$LIBRARY_DIR/authors"

mkdir -p "$LIBRARY_DIR/prices"
chmod 750 "$LIBRARY_DIR/prices"
sudo chown :"$GROUP_NAME" "$LIBRARY_DIR/prices"

mkdir -p "$LIBRARY_DIR/.tmp"
chmod 770 "$LIBRARY_DIR/.tmp"
sudo chown :"$GROUP_NAME" "$LIBRARY_DIR/.tmp"
```

Все было разобрано <s>на лекциях</s> выше.

Можно посмотреть на готовую структуру, запустив скрипт:
